# KNEST UI/UX review

Reviewer: UI/UX reviewer (review only; no source was edited, built or run).
Branch: `delivery/p1-containment`. Date: 2026-10-09.

Method: every file in `src/components/ui`, `src/components/layout`, `src/components/labs`, and the route groups `(public)`, `(member)`, `(staff)`, `(auth)` was read against `.claude/rules/*.md`. Contrast ratios were computed from the values in `src/styles/tokens.css`. Nothing was run in a browser, so findings marked "verify" are inferences from the code.

Paths are relative to `src/`. Two files, `components/layout/site-header.tsx` and `app/(staff)/admin/layout.tsx`, were being edited by a teammate while this review ran; their line numbers are from the working tree at review time and may move. Accessibility findings overlap with `docs/handover/ACCESSIBILITY-REVIEW.md`; the items below were cross-checked with that reviewer, and file:line refs match.

## Score (rubric from `.claude/rules/review-and-research.md`)

| Dimension | Weight | Score | Why |
|-----------|--------|-------|-----|
| Visual Hierarchy | 20% | 6/10 | Strong identity (oxblood, brass, Fraunces) and good lead items on analytics and the program detail. Weak on the member dashboard (greeting outshouts the next-step card), the admin overview (equal tiles) and the page headers (30/36px "display"). |
| Consistency | 20% | 4/10 | Five button shapes, three form-control styles, two status-badge systems, three h1 scales, 24 uses of an undefined border token. Lab booking and admin are built from raw elements instead of the design system. |
| Accessibility | 20% | 5/10 | Good bones (skip link, global focus ring, live regions, labelled fields, sr-only status text). Fails: form-control border 1.34:1, unlabelled admin select, no focus indicator on the file input, radio/tab semantics, sub-24px targets. |
| Usability | 20% | 6/10 | Honest copy and thoughtful empty states, but dead anchors, a no-op "Notify me", lost `next` on auth cross-links, buttons that hang on network failure, no confirms on destructive admin actions. |
| Responsiveness | 10% | 5/10 | The public site is solid. Lab booking and the lab console have no page gutters and several `min-w-[16-18rem]` inputs. The mobile nav panel needs a real-browser check. |
| Performance | 10% | 4/10 | 0.5-0.9 MB unoptimised JPEGs in raw `<img>`, a hidden 814 KB `priority` image on phones, a full-viewport `mix-blend-multiply` noise layer, hero text hidden until hydration, 700-2000 ms transitions. |
| **Overall** | **100%** | **5.1/10** | (0.2 x 21) + (0.1 x 9) |

Nielsen heuristics most violated: #1 visibility of system status (loading shown as disabled, false "Sent"), #5 error prevention (no confirms), #4 consistency, #9 error recovery (generic messages, hung states), #3 user control.

## Cross-reference with the accessibility review

Agreed with `ACCESSIBILITY-REVIEW.md`: C3 (control border), M1 (undefined token), M22 (unlabelled select), M18 (header containing block, needs a real browser), m2 (positive tag 4.27:1), m7 (radio/tab semantics), m15 (target size), M7 (loading as disabled). One correction: admin table links (`admin/applications/page.tsx:32`) are not a text-contrast failure. Signal on the admin paper-soft background is 8.04:1; the issue is that links have no underline, so only colour separates them from body text (WCAG 1.4.1). Add `underline underline-offset-4` to admin links.

Items the accessibility reviewer raised that sit outside this report's remit but affect the UX fixes above: focus is lost and nothing is announced after approve, cancel, remove, mark-read, resend and step changes; `Field` error wiring is never used by any caller; every application answer is labelled "Your answer" (`application-form.tsx:252,266`); a blocked Turnstile script disables every submit button with no message (`turnstile-widget.tsx:73,86`); no forced-colors rules. Fold these into the same `Button loading`, `Field` and `postJson` work in M5, M7 and M19.
