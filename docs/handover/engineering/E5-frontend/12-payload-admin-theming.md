# E5.12 Payload admin theming

Files: `src/app/(payload)/layout.tsx`, `(payload)/admin/[[...segments]]/page.tsx`, `(payload)/admin/importMap.js`, `(payload)/api/[...slug]/route.ts`, `src/payload/custom-admin.css`, `src/payload/components/{Branding,BeforeDashboard}.tsx`, `src/payload/payload.config.ts:35-47`, `next.config.ts` (CSP).

## 1. Mounting

- `(payload)/layout.tsx:10-26` renders Payload's `RootLayout` with `config`, `importMap` and a `serverFunction` wrapper marked `'use server'` that forwards to `handleServerFunctions`. It first calls `requireStaff()` (`:19`), which calls `notFound()` for anyone without a staff role, so a non-staff visitor sees the KNEST 404 rather than Payload's "unauthorised" screen (which would be HTTP 200, `:16-18`).
- `admin/[[...segments]]/page.tsx` delegates to `RootPage` and `generatePageMetadata` (`:11-17`). `api/[...slug]/route.ts` exports the REST handlers for GET, POST, PUT, PATCH, DELETE and OPTIONS (`:11-16`). The route group keeps these out of the public layout: no site header, footer or skip link.
- Access is enforced twice: the layout guard and Payload's own access control through the Auth.js strategy in `src/payload/auth-strategy.ts` (comment `layout.tsx:1-2`). Staff accounts are a read-only mirror: `admin.user` is the `staff` collection while real accounts live in `app.users` (`payload.config.ts:31-35`).
- `importMap.js` is generated by Payload (`npx payload generate:importmap` or on dev). It lists Lexical client features plus `Branding#Icon`, `Branding#Logo`, `BeforeDashboard`, `CollectionCards`, `S3ClientUploadHandler`. When a custom component path is added in `payload.config.ts`, this file must be regenerated and committed or the admin throws at render. It is generated code; do not hand-edit.

Open question, not determined from the code: `src/app/layout.tsx` already renders `<html><body>`, and Payload's `RootLayout` is documented in Payload's own template as the layout that renders `<html>` and `<body>`. Nested document elements would be invalid and produce a hydration warning in development. No test scans a Payload page for this (the staff axe list covers only `/admin/overview` and the custom console pages, `35-accessibility.test.ts:170`). The boot test and manual use evidently work, so the effect may be benign, but it should be checked once in a browser on `/admin`.

## 2. Theming layers

1. `'@payloadcms/next/css'` (Payload base styles) is imported first, then `@/payload/custom-admin.css` (`layout.tsx:8-9`). Order matters: the custom file relies on `!important` and on being later in the cascade.
2. `custom-admin.css:2` imports the site `tokens.css`, so `--color-*`, `--radius-*` and `--motion-*` resolve inside the admin. Because `tokens.css` contains an `@theme` at-rule, it is processed by the Tailwind PostCSS plugin (`postcss.config.mjs`). Whether Tailwind emits every theme variable into the admin bundle or only those it sees used was not determined; the admin rules reference `var(--color-...)` directly, which Tailwind v4 is documented to keep, not verified here.
3. Overrides (`custom-admin.css`):
   - `html[data-theme='light']` (`:4-22`): font variables to 'Inter' and 'Fraunces', elevation scale to paper tones, success colours to oxblood, text colours. Only the light theme is themed; Payload's dark theme (if a staff member selects it) keeps Payload's palette except for the global rules below.
   - `.nav` paper background with a line border and `.nav *` forced to ink with `!important` (`:25-32`), group toggles in signal uppercase serif, active link with a 3px signal left rule (`:34-50`).
   - `.btn` signal background, uppercase, square (`:59-83`); secondary buttons transparent with signal border and text.
   - `.card` square, bordered, no shadow (`:86-91`); table header uppercase.
   - `.knest-dashboard` typography for the `BeforeDashboard` panel (`:109-116`).
4. Branding: `Logo` and `Icon` render `/images/knest_logo.png` and `/images/knest_icon.png` with plain `<img>` and inline styles (`Branding.tsx:3-27`). The logo has `alt="KNEST"`.
5. `BeforeDashboard` is an async server component placed before Payload's collection cards (`payload.config.ts:42`). It counts published startups, upcoming published events and staff, with filters matching its labels (KN-32 comment), and renders three bordered cards with inline style objects referencing token variables (`BeforeDashboard.tsx:19-50`). Counts use the local API with default access (no `overrideAccess: false`), which is correct here because the viewer is already authorised staff.
6. Collection grouping in the sidebar is assigned in config: Incubator, Ecosystem, Content, System (`payload.config.ts:70-82`).

## 3. Constraints and failure modes

- **Fonts do not load in the admin.** `custom-admin.css:6-7` names `'Inter'` and `'Fraunces'` as literal family names. The site fonts are Fraunces and Instrument Sans loaded by `next/font`, which registers hashed family names behind variables set on `<html>` by the root layout; `Inter` is not loaded anywhere (`fonts.ts`). The admin text therefore falls back to `sans-serif`/`serif` unless the viewer has those fonts installed. This is inferred from the code, not observed. The rule `.nav .nav-group__toggle { font-family: var(--font-display) }` (`:36`) resolves to the same overridden value.
- **Literal colours remain.** `custom-admin.css:10-21` still holds `#f6f4ee`, `#f0eee8`, `#76232f`, `#5c1b24`, `#1a1a1a`, `#4a4a4a`. `TOKEN-PIPELINE.md:38,43` says these were replaced by tokens; they were only replaced for the selectors below line 24. The lint exempts `--name: value` lines (E5.09), which is why CI is green.
- **Brittle selectors.** `.nav`, `.btn`, `.card`, `table th` target Payload's internal class names, which are not a public API. A Payload upgrade (the repo pins `3.90.2` for all `@payloadcms/*`, `package.json:32-36,46`) can rename them silently; nothing tests the admin's appearance.
- **Global leakage.** The selectors are unscoped (`.btn`, `.card`, `table th`). Next bundles a layout's CSS with the routes under that layout, so public pages do not receive these rules on a fresh load; behaviour across client-side navigation from `/admin` to a public page was not determined. The custom admin console (`(staff)/admin/*`) uses its own Tailwind classes, not these rules.
- **Contrast.** `.btn *` forces `--color-paper-raised` text on `--color-signal` (about 9:1 per the token comment). `.nav *` forces ink on paper. No check covers Payload's disabled, error or focus states under these overrides (`!important` on `border` and `background-color` can remove Payload's focus and disabled differentiation).
- **CSP.** The admin needs `'unsafe-inline'` for scripts and styles; `next.config.ts:7-16` records that this was confirmed by loading `/admin` in report-only mode. `img-src` additionally allows `https://www.gravatar.com` for the account avatar (`:23-25`).
- **Upload limit.** The proxy buffer is raised to 12 MB so 10 MB uploads (with multipart overhead) are not truncated (`next.config.ts:63-68`); this also applies to admin media uploads.
- **Media storage.** `s3Storage` is enabled only when `S3_BUCKET` is set; otherwise Payload writes to local disk, which is lost on container replacement (`payload.config.ts:86-95`).
- **Title suffix.** The comment at `payload.config.ts:33-34` says no `meta.titleSuffix` is set to avoid "Dashboard — KNEST — KNEST", yet `meta: { titleSuffix: ' — KNEST' }` is set at `:44-46`. Either the comment or the setting is stale; the effective admin title was not observed.

## 4. Changing the theme safely

1. Edit `tokens.css` for anything shared; the admin follows through `var()`.
2. Replace the hex block at `custom-admin.css:10-21` with token references (for example `var(--color-paper)`), remembering Payload variables expect colour values.
3. Load the real fonts: reference `var(--font-display-family)` and `var(--font-text-family)` or add `next/font` variables to Payload's layout `<html>` class (needs the nested-document question in section 1 resolved first).
4. After any Payload upgrade, open `/admin`, a collection list, an edit view with rich text, and the media library in light and dark.
