## 3. Access helpers (`src/payload/access.ts`)

| Helper | Lines | Returns |
|---|---|---|
| `roleOf(user)` | 5-8 | `staffRole` string from `req.user`, else `null` (never trusts types) |
| `canWrite(area)` | 18-21 | `Access`: `canAccessArea(roleOf(req.user), area)` |
| `canWriteField(area)` | 23-26 | `FieldAccess`, same test; used for the `metrics.source` read restriction |
| `readPublished` | 32-35 | any staff role: `true` (sees drafts); anonymous and non-staff: the query constraint `{ _status: { equals: 'published' } }` |
| `isAnyStaff` | 37 | `roleOf(user) !== null` (exported; no other reference found in `src/`) |
| `readAlways` | 46 | `true`, for collections that have no `_status` |

Why two read helpers: `readPublished` filters on `_status`, which exists only on collections with
`versions.drafts`; applying it to Cohorts, Testimonials, FAQs or Metrics throws "Cannot find field for
path at _status" (`access.ts:39-45`).

Important property: **any** staff role, including `reviewer`, sees unpublished drafts of **every**
draft-enabled collection through `readPublished` (lines 32-35). Write is scoped by area; read of
drafts is not.

## 5. Things the matrix implies for privacy and operations

- **Everything in an `readAlways` or `read: () => true` collection is public over REST.** That
  includes testimonials with `attribution`, `role` and `photo`; cohorts; FAQs; metrics except
  `source`; and every media file URL.
- **Draft-state and unpublish.** `readPublished` makes unpublishing a real privacy control for
  startups, founders, mentors and partners (public profiles of named people). `founders.userId` and
  `mentors.userId` are plain fields with no field-level access, so they are returned to anonymous
  readers of a published profile; they contain the internal `app.users.id` UUID (see D-08).
- **Field-level read restriction exists once** (`metrics.source`). No field in `founders` or
  `mentors` has one.
- **No `delete` restriction beyond role.** Only Programs has a delete guard (`14`).
- **Staff mirror read** is any staff role, so any staff user can read the e-mail and role of every
  other staff user through `/api/staff`. No field-level restriction.
- **Locks.** Payload's document-locking tables exist (`payload_locked_documents`); no `lockDocuments`
  setting is overridden in config. Default behaviour not determined from the code.
- **GHSA-jg8r-5jh2-v2xj** (account unlock) is neutralised by `unlock: () => false`
  (`staff.ts:34-37`); asserted by `access.test.ts:114`.
